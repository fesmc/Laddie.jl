Entry points

Laddie.Grid — Type
struct Grid{FT, A<:(AbstractMatrix), V<:(AbstractVector), I, M<:(AbstractMatrix), R, S}

The model grid: a cropped rectangle of cells with its mask, ice draft and bed. Construct with Grid(mask, z_draft, dx, dy; ...) and pass it to Model.

The grid knows nothing about boundary conditions or physics: a gap cell (4) is kept as such whatever the gaps treatment, the masks the solver uses are derived by the model, and so are the ice-base slope and the Coriolis field.

Fields

  • Nx::Any: total cells in x, including the one-cell border ring

  • Ny::Any: total cells in y, including the one-cell border ring

  • dx::Any: cell spacing in x (m)

  • dy::Any: cell spacing in y (m)

  • mask::AbstractMatrix: cell classification after preprocessing and cropping; gaps still marked 4 (CPU)

  • z_draft::AbstractMatrix: ice-base depth (m, ≤ 0), zeroed outside grounded ice and shelf

  • z_bed::AbstractMatrix: bed elevation (m); -Inf when none was given (no cap on the layer thickness)

  • x::AbstractVector: interior cell-centre x coordinates (m, CPU)

  • y::AbstractVector: interior cell-centre y coordinates (m, CPU)

  • crop::Any: row and column ranges of the input arrays that the grid keeps

  • input_size::Any: size of the input arrays, before cropping

Laddie.Model — Type
mutable struct Model{G<:Grid, GE<:Laddie.Geometry, S<:State, C<:Cache, P<:Params, B<:BoundaryConditions, F<:CavityForcing}

The model: geometry, physics and prognostic state. It knows nothing about time integration — wrap it in a Simulation to advance it with run!.

The fields are Matrix{FT} on CPU and CuArray{FT,2} on GPU. Use to_backend(m, backend) to obtain a model on a different backend — it returns a new Model with the matching array types.

Fields are accessed directly on m through a flat forwarding layer:

  • geometry::Laddie.Geometry: masks, wall indicators, ice-base slope and Coriolis field derived from the grid

  • state::State: the prognostic fields H, U, V, T, S

  • cache::Cache: diagnostic and scratch fields, updated in place every step

  • params::Params: physical constants and parameterisation choices (Params)

  • boundary::BoundaryConditions: boundary conditions (BoundaryConditions)

  • forcing::CavityForcing: ocean and ice forcing (CavityForcing)

Laddie.run! — Function
run!(sim::Simulation; days, until, verbose) -> Simulation

Advance simulation sim until the criterion until is met.

until is an AbstractSimulationEnd measured from the clock time at which run! is called: FixedSimulationEnd runs for a fixed duration, SteadyStateEnd stops early once the mean melt rate is quasi-steady. It defaults to sim.stop; as a shorthand, run!(sim; days = 30.0) is equivalent to run!(sim; until = FixedSimulationEnd(t_end = 30.0)).

The clock is never reset, so successive calls continue the same simulation: run!(sim; days = 10); run!(sim; days = 10) ends at day 20, and output and restart files are stamped accordingly. Each call rounds its own duration to a whole number of steps, so a sequence of calls matches one long call exactly only when the durations are multiples of dt.

Each step is one time_step!. When sim.output.saveday > 0, the output fields are accumulated after every step, savefields!, printdiags and saverestart! write whenever their interval is due, and the call ends by flushing the partial averaging window and writing a restart. When verbose = true, a progress bar with throughput and ETA is displayed; melt/thickness/speed diagnostics attached to the bar refresh every ~5 % of steps (they are device reductions, so they are deliberately not per-step).

Before stepping, a warning is emitted if the advective CFL number at the velocity cap v_cut exceeds 1. Every ~5 % of steps the prognostic fields are checked for non-finite values; on blow-up the run aborts with an error instead of integrating NaNs.

Returns sim for chaining.

Laddie.time_step! — Function
time_step!(sim::Simulation) -> Simulation

Advance sim by one leapfrog time step: advance_leapfrog! → leapfrog_step! (2×dt, which ends each momentum step with clamp_velocities!) → apply_robert_asselin_filter!, then move the clock forward by dt. No I/O, no CFL control, no blow-up check — those belong to run!.

Returns sim.

Laddie.meltstats — Function
meltstats(
    sim::Simulation
) -> NamedTuple{(:max_meltrate, :mean_meltrate, :max_speed, :total_melt), <:NTuple{4, Any}}

Return melt-rate and velocity statistics for the current state of a model or simulation, as a named tuple. All reductions execute on the device (GPU-safe); results are returned as CPU scalars.

  • max_meltrate — maximum basal melt rate, m yr⁻¹
  • mean_meltrate — area-mean basal melt rate over ice-covered cells, m yr⁻¹
  • max_speed — maximum depth-averaged current speed |u|, m s⁻¹
  • total_melt — area-integrated basal melt (mass flux), Gt yr⁻¹

Melt rates are freshwater equivalent, the unit the model integrates; multiply by rho_freshwater / rho_ice for ice equivalent. total_melt is the corresponding mass flux, Σ melt · dx · dy · rho_freshwater, and is the same in either unit.

The fields keep their order, so max_melt, mean_melt, max_speed = meltstats(sim) still destructures the first three.

The melt statistics average over imask (ice-covered cells), not tmask. Under ConnectedGapsBC the two differ: gap cells are dynamically active but ice-free and melt exactly zero, so averaging over tmask would dilute the mean by the gap area. This diverges from LADDIE v2, whose domain_a integration includes gaps; with no gaps in the mask the two masks coincide and the statistics are unchanged. max_speed stays on tmask — the layer really does flow through gaps, and that flow is the point.

to_backend(

Return a new simulation whose model and I/O accumulators live on backend. The clock, time stepper and output configuration are carried over; the original simulation is not modified.

With a ReactantBackend, run! then advances the simulation in compiled batches of steps (requires using Reactant, CUDA).

source
to_backend(m::Model, backend)

Return a new model with all floating-point arrays transferred to backend. The original model is not modified; always assign the result:

using CUDA
model = Model(Grid(mask, z_draft, dx, dy); forcing)
model = to_backend(model, CUDABackend())
sim = Simulation(model)

Prefer passing backend directly to Grid or build_isomip where possible — it avoids the redundant CPU allocation:

sim = build_isomip(CUDABackend(); FT = Float32)

Running on Reactant

See Reactant backend for the setup, the fusion strategies and their cost, and Automatic differentiation for differentiating a run.

Laddie.ReactantBackend — Type
struct ReactantBackend{F, M, P}

Run a simulation through Reactant.jl: the time step is traced, compiled with XLA and executed in batches of steps, on the GPU or the CPU that Reactant targets. Requires using Reactant, CUDA (CUDA.jl is needed even for the CPU target, since Reactant compiles the kernels through it).

using Laddie, Reactant, CUDA
sim = build_isomip(CPU(); FT = Float32)          # build and bootstrap on the CPU
rsim = to_backend(sim, ReactantBackend())        # move to Reactant
run!(rsim; days = 30)                            # compiled on the first call

With a mesh (a Reactant.Sharding.Mesh), the grid is split over several devices: every field is sharded along partition, one mesh axis name (or nothing) per grid axis, and XLA exchanges the halos between the devices. The default partition splits the second grid axis (contiguous slabs) over a one-axis mesh, and both grid axes over a two-axis mesh. Each split grid axis must be divisible by its number of devices: crop with MinRectangleDomainCropping(; multiple) to round the grid up. The native kernels of the GPU default cannot be split, so on a mesh fusion = :auto raises them: :kernel over one mesh axis, :xla over two.

mesh = Reactant.Sharding.Mesh(collect(0:3), (:y,))          # 4 devices
crop = MinRectangleDomainCropping(; multiple = (1, 4))
grid = Grid(mask, z_draft, dx, dy; domain_cropping = crop)
rsim = to_backend(Simulation(Model(grid; forcing)), ReactantBackend(; mesh))

Results agree with the KernelAbstractions backends to round-off, not bit for bit: XLA reorders floating-point operations.

Fields

  • fusion::Any: how XLA may fuse the kernels of a step (see the Reactant docs page); :auto picks the measured best

  • mesh::Any: device mesh to shard the grid over, a Reactant.Sharding.Mesh; nothing for one device

  • partition::Any: mesh axis name (or nothing) each grid axis is split along; nothing for the default

Laddie.build_laddie_mask — Function
build_laddie_mask(bed, thickness; rho_ice, rho_sw) -> Any

Derive the 4-class LADDIE domain mask from BedMachine-style bed-elevation and ice-thickness arrays. Both arrays should cover the interior domain of size (nx, ny); the returned mask has size (nx+2, ny+2) with a one-cell border ring of 1 (land/boundary).

ValueMeaningCondition
0open oceanthickness ≤ 0 and bed < 0
1landthickness ≤ 0 and bed ≥ 0; border ring
2grounded icethickness > 0 and h_af ≥ 0
3floating shelfthickness > 0 and h_af < 0

Height above flotation: h_af = thickness × (rho_ice/rho_sw) + bed. Gaps (4) are not derived here; mark them with MarkGapsPreprocess.

Ice-free cells are split by bed elevation, which is the thickness → 0 limit of the flotation test: exposed bedrock — nunataks, rock islands inside a shelf, ice-free coastline — is land, not ocean. Were it ocean, every such island would act as an open-boundary sink in the middle of the cavity.

The default densities are BedMachine's (917 and 1028 kg m⁻³), so the mask agrees with the dataset's own; they need not match the model's Params.rho_ice.

Arguments

  • bed: bed elevation (m, positive above sea level).
  • thickness: ice thickness (m, positive where ice is present).
  • rho_ice: ice density (kg m⁻³, default 917).
  • rho_sw: seawater density (kg m⁻³, default 1028).

Example

ds    = NCDataset("BedMachineAntarctica-v3.nc")
z_bed = Float64.(Array(ds["bed"][i1:i2, j1:j2]))
h_ice = Float64.(Array(ds["thickness"][i1:i2, j1:j2]))
close(ds)
mask = build_laddie_mask(z_bed, h_ice)

Laddie.ice_base_depth — Function
ice_base_depth(bed, thickness; rho_ice, rho_sw) -> Any

Compute ice-base depth (m, negative below sea level) from BedMachine-style arrays. Returns a (nx+2, ny+2) matrix (interior domain with border ring zeroed).

  • Floating cells (h_af < 0): z_draft = -thickness * rho_ice/rho_sw (Archimedes).
  • Grounded cells (h_af >= 0): z_draft = bed (ice base rests on the bed).
  • Ocean / border cells: z_draft = 0.

Pass the result directly as the z_draft argument of Grid, which clamps very shallow shelf cells and zeroes the draft outside grounded ice and shelf.

Arguments

  • bed: bed elevation (m, positive above sea level).
  • thickness: ice thickness (m, positive where ice is present).
  • rho_ice: ice density (kg m⁻³, default 917).
  • rho_sw: seawater density (kg m⁻³, default 1028).

Laddie.fill_ocean_holes! — Function
fill_ocean_holes!(mask::AbstractMatrix{Int64}) -> Int64

Remove isolated ocean pockets from a LADDIE mask by flood-filling from the main ocean. Ocean cells (mask == 0) that are not connected (4-connectivity) to the outer ocean are reclassified as land (mask == 1).

The outer ocean is identified as all ocean cells reachable from the outermost ring of the array. Noisy topography (e.g. BedMachine) occasionally creates small enclosed ocean patches fully surrounded by ice; these cause spurious ice-front dynamics and numerical instabilities.

An enclosed pocket becomes land, not grounded ice: there is no ice there, and conflating the two hides which walls are rock and which are the grounding line.

Modifies mask in-place and returns the number of cells that were reclassified.

Arguments

  • mask: integer mask matrix as returned by build_laddie_mask.

Example

mask = build_laddie_mask(z_bed, h_ice)
n = fill_ocean_holes!(mask)
println("Reclassified $n isolated ocean cells")

Laddie.fill_shelf_holes! — Function
fill_shelf_holes!(mask::AbstractMatrix{Int64}) -> Int64

Remove isolated floating-shelf patches from a LADDIE mask by flood-filling from shelf cells connected to the open ocean. Shelf cells (mask == 3) that have no 4-connected path to any ocean cell (mask == 0) are reclassified as grounded ice (mask == 2).

Noisy topography can produce small shelf patches fully enclosed by grounded ice with no ice front; these are physically inconsistent and can cause instabilities.

Modifies mask in-place and returns the number of cells reclassified. Call fill_ocean_holes! first so that isolated ocean pockets do not artificially seed shelf connectivity.

Arguments

  • mask: integer mask matrix as returned by build_laddie_mask.

Example

mask = build_laddie_mask(z_bed, h_ice)
fill_ocean_holes!(mask)
n = fill_shelf_holes!(mask)
println("Reclassified $n isolated shelf cells")

Laddie.fill_small_shelf_patches! — Function
fill_small_shelf_patches!(
    mask::AbstractMatrix{Int64}
) -> Any
fill_small_shelf_patches!(
    mask::AbstractMatrix{Int64},
    min_cells::Int64
) -> Any

Remove undersized floating-shelf patches from a LADDIE mask. Each 4-connected component of shelf cells (mask == 3) is identified; any component with fewer than min_cells cells is reclassified as grounded ice (mask == 2).

A component of only a few cells cannot meaningfully resolve the LADDIE plume dynamics: the centred-difference stencil spans ≥ 2 cells in each direction, and the depth-averaged momentum balance requires at least O(10) cells to develop a coherent flow. Removing these micro-patches eliminates spurious gradients and numerical instabilities in noisy real-world topography (e.g. BedMachine).

Modifies mask in-place and returns the number of cells reclassified. Recommended to call fill_ocean_holes! and fill_shelf_holes! first.

Arguments

  • mask: integer mask matrix as returned by build_laddie_mask.
  • min_cells: minimum number of cells a shelf component must have to be retained (default 10). Components strictly smaller than this are removed.

Example

mask = build_laddie_mask(z_bed, h_ice)
fill_ocean_holes!(mask)
fill_shelf_holes!(mask)
n = fill_small_shelf_patches!(mask, 20)
println("Removed $n cells in undersized shelf patches")

Laddie.fill_small_grounded_patches! — Function
fill_small_grounded_patches!(
    mask::AbstractMatrix{Int64}
) -> Any
fill_small_grounded_patches!(
    mask::AbstractMatrix{Int64},
    min_cells::Int64
) -> Any

Remove undersized isolated grounded-ice patches from a LADDIE mask. Each 4-connected component of grounded cells (mask == 2) that is not connected to the outermost ring of the array is identified; any such component with fewer than min_cells cells is reclassified as floating shelf (mask == 3).

Components that touch the border ring are part of the main grounded ice sheet and are never modified, regardless of size. Only truly isolated grounded patches — pinning points, rumples, or topographic artefacts inside the shelf — are candidates for removal.

Modifies mask in-place and returns the number of cells reclassified. Recommended to call fill_ocean_holes! and fill_shelf_holes! first so that the shelf geometry is clean before removing pinning points.

Arguments

  • mask: integer mask matrix as returned by build_laddie_mask.
  • min_cells: minimum number of cells an isolated grounded component must have to be retained (default 10). Components strictly smaller than this are reclassified as shelf.

Example

mask = build_laddie_mask(z_bed, h_ice)
fill_ocean_holes!(mask)
fill_shelf_holes!(mask)
n = fill_small_grounded_patches!(mask, 20)
println("Reclassified $n cells in undersized isolated grounded patches")

Model container

Laddie.Params — Type
struct Params{FT, EP<:AbstractEntrainment, MP<:AbstractMelting, CS<:AbstractConvectionScheme, FZ<:AbstractFrazilIce, IC<:AbstractIceConduction, EQ<:AbstractEquationOfState, MLT<:AbstractMaxLayerThickness, LV<:AbstractLateralViscosity, LW<:AbstractLaplacianWeights, FP<:AbstractFrontPressure, MA<:AbstractMomentumAdvection, TF<:AbstractTracerForm, MF<:AbstractMomentumForm, CL<:AbstractClosureLevel, CP<:AbstractCoriolisParameter, KT<:AbstractKinks}

All physical constants and parameterization choices of a Model, in one immutable, concretely typed struct. Build it with the keyword constructor Params(; ...), which fills in the ISOMIP+-canonical defaults. Time integration is configured on the Simulation, and the boundary conditions in BoundaryConditions.

Rates follow the model's convention: melt and the entrainment rates are freshwater-equivalent layer-thickness rates in m s⁻¹, and $\delta\rho$ is the reduced density contrast $(\rho_a - \rho)/\rho_0$.

Fields

  • g::Any: gravitational acceleration (m s⁻², default 9.81)

  • C_d::Any: quadratic drag coefficient of the layer against the ice base, momentum equations (–, default 2.5e-3)

  • C_d_top::Any: drag coefficient in the friction velocity u★ that drives melt and entrainment (–, default 1.1e-3)

  • A_h::Any: lateral momentum viscosity, and the wall-drag coefficient under every viscosity scheme (m² s⁻¹, default 6)

  • K_h::Any: lateral tracer diffusivity (m² s⁻¹, default 1)

  • max_detrainment::Any: upper bound on the detrainment rate (m s⁻¹, default 1e6, i.e. unbounded)

  • drho_floor::Any: lower bound on δρ in the buoyancy-entrainment production term, which divides by it (–, default 1e-4)

  • H_min::Any: minimum layer thickness, kept by extra entrainment and a final clamp (m, default 1)

  • v_cut::Any: speed cap applied to the velocity after each momentum step (m s⁻¹, default 1.414)

  • u_tide::Any: tidal velocity added in quadrature in the friction velocity (m s⁻¹, default 0.01)

  • rho_freshwater::Any: freshwater density, for the melt mass flux (kg m⁻³, default 1000)

Laddie.Cache — Type
mutable struct Cache{A<:(AbstractMatrix), GamT, Conv2, Frz, PM}

Pre-allocated diagnostic and scratch fields of a Model, updated in place every time step. The physics outputs are read through the model, e.g. model.melt (m s⁻¹), model.entr, model.drho, model.ustar, model.Ta.

A is the concrete matrix type (matching the grid and state). The scheme-dependent slots are scalars or fields: GamT (gamT, gamS) is a field for TurbulentGamTMelting, UStarGamTMelting and PrescribedMelting, Conv2 (conv2) for RelaxToAmbient, Frz (frazil) for RelaxedFrazilIce, and PM (melt_prescribed) for PrescribedMelting.

adv, lap and Hq are shared by the four stepped equations: U, V, T and S are stepped one after another, and each consumes its terms before the next one writes them. In between, adv and lap hold the speed limiter's per-point scale factors. NonlinearLateralViscosity fills Hq with the collocated cross-velocity and adv with the thickness on the velocity points before its Laplacian kernel, which is why the momentum steps form the Laplacian before the advection term. diag is never read by the time step, so any host-side diagnostic may overwrite it.

  • melt::AbstractMatrix: basal melt rate (m s⁻¹)

Ocean

The ocean forcing types are described in Ocean forcing.

From a 3D ocean field

Ocean models that force ice-sheet models mostly have no ice-shelf cavities. front_ocean_forcing gives every cavity cell the water column at the ice front that feeds it; regrid_ocean and fill_ocean! bring a coarse ocean grid onto the model's cells.

Laddie.front_ocean_forcing — Function
front_ocean_forcing(T, S, z, mask; depth = nothing, FT = Float64)

Ambient forcing from outside the ice fronts only, as an ocean model without cavities would give it: every cavity cell of mask takes the water column of its open-ocean source (front_sources), extended flat below that column's water. T, S are (nx, ny, nz) on the depths z (uniform) for the full domain of mask, border ring included, with NaN where there is no water; only cells with water in both can be sources. depth ranks the open-ocean neighbours of a front cell, the lowest winning (pass the bed elevation, size of mask); without it, the column with the most levels of water wins.

Returns a PerBasinOceanForcing1D with one profile per source column: n_sources × nz numbers instead of the full 3D field. Cells outside the cavities take the profile of the nearest cavity cell, so every cell has one.

source
Laddie.front_sources — Function
front_sources(mask; wet = trues(size(mask)), depth = nothing) -> (source, lost)

The open-ocean cell whose water column forces each cavity cell, on a Laddie mask (border ring included, as Grid takes it):

  • open ocean: the 0 cells connected (4-neighbour) to the edge of the domain;
  • cavity: floating ice (3), gaps (4) and enclosed water (0 cells not connected to the open ocean);
  • a cavity cell next to open ocean takes the deepest such neighbour that is wet (has water data) as its source: the one with the lowest depth (a matrix the size of mask, e.g. the bed elevation), or the first when depth is not given;
  • every other cavity cell takes the source of the front nearest through the cavity (8-neighbour chamfer distance), so that no front reaches across grounded ice or land;
  • cavity cells that no front reaches, the source of the nearest front in a straight line.

Returns the linear index into mask of the source of every cavity cell (0 elsewhere), and the number of cavity cells that took a straight line.

nearest_seed(labels) -> (label, d2)

For every cell of the matrix labels, the label of the nearest seed (a cell with labels > 0) and the squared distance to it in cells², by exact Euclidean distance (Felzenszwalb & Huttenlocher 2012: the 1D lower-envelope transform along the columns, then along the rows). Laddie.regrid_ocean — Function
regrid_ocean(T, S, x, y, px, py) -> (; T, S)

Bilinear interpolation of the 3D ocean fields T, S ((length(x), length(y), nz) on the ascending axes x, y, NaN or missing where there is no water) to the points px × py, level by level, flat beyond the axes. Laddie.AbstractIceForcing — Type

source
Laddie.PrescribedIceForcing — Type
struct PrescribedIceForcing{M} <: AbstractIceForcing

Ice temperature $T_i$ held fixed for the whole run.

Despite its name, T_ice_base is not the temperature at the ice base: the base is at the interface temperature $T_b$, the freezing point, which the melt solve computes every step. The ice column is not resolved; the heat conducted into the ice is a parameterisation (AbstractIceConduction), and $T_i$ is the temperature of the ice above the thin thermal boundary layer at the base, into which the ice is advected as it melts. For the default HollandJenkinsConduction (Holland & Jenkins 1999), a steady ice column, that is the ice-shelf surface temperature (Wiskandt & Jourdain 2025 use the 1980–2019 mean snow-surface temperature). With an ice sheet model at hand, the ice temperature 50–100 m above the base, as a 2D field, carries the transient and upstream-advected state of the ice instead. Were $T_i$ the basal temperature, $T_i = T_b$ and it would have no effect.

T_ice_base may be given as a scalar (uniform ice, the common standalone case) or as a full-domain matrix the same size as mask, letting a colder interior sit next to a temperate ice front. Model converts either form to an FT matrix on the model grid, cropping it alongside the mask, so m.T_ice_base is always a grid-shaped field.

Colder ice absorbs more heat per unit melt, so a lower T_ice_base means less melt for the same thermal driving: L_eff runs from 3.34e5 J kg⁻¹ at 0 °C to 3.84e5 at −25 °C, a 15 % spread.

PrescribedIceForcing(-25.0)          # uniform, the default
PrescribedIceForcing(T_ice_matrix)   # 2D, same size as `mask`

Fields

  • T_ice_base::Any: ice temperature above the basal boundary layer, typically the surface temperature (°C): a scalar, or a full-domain matrix the size of mask
