Entry points

Laddie.Grid — Type
struct Grid{FT, A<:AbstractMatrix, V<:AbstractVector, I, M<:AbstractMatrix, R, S}

The model grid: a cropped rectangle of cells with its mask, ice draft and bed. Construct with Grid(mask, z_draft, dx, dy; ...) and pass it to Model.

The grid knows nothing about boundary conditions or physics: a gap cell (4) is kept as such whatever the gaps treatment, the masks the solver uses are derived by the model, and so are the ice-base slope and the Coriolis field.

Fields

  • Nx::Any: total cells in x, including the one-cell border ring

  • Ny::Any: total cells in y, including the one-cell border ring

  • dx::Any: cell spacing in x (m)

  • dy::Any: cell spacing in y (m)

  • mask::AbstractMatrix: cell classification after preprocessing and cropping; gaps still marked 4 (CPU)

  • z_draft::AbstractMatrix: ice-base depth (m, ≤ 0), zeroed outside grounded ice and shelf

  • z_bed::AbstractMatrix: bed elevation (m); -Inf when none was given (no cap on the layer thickness)

  • x::AbstractVector: interior cell-centre x coordinates (m, CPU)

  • y::AbstractVector: interior cell-centre y coordinates (m, CPU)

  • crop::Any: row and column ranges of the input arrays that the grid keeps

  • input_size::Any: size of the input arrays, before cropping

Laddie.Simulation — Type
struct Simulation{M<:Model, CL<:Clock, TS<:AbstractTimeStepper, C<:AbstractCFL, N, E<:AbstractSimulationEnd, O<:OutputConfig, IOS<:Laddie.IOState, D<:DebugConfig, X<:Laddie.AbstractExecution}

A Model together with its time integration and I/O. Construct with Simulation(model; ...) and advance with run!.

Fields

  • model::Model: the model being integrated

  • clock::Clock: simulated time, iteration count and current dt

  • time_stepper::AbstractTimeStepper: how dt evolves: FixedTimeStepper or AdaptiveTimeStepper

  • cfl::AbstractCFL: how the in-loop CFL number is computed: ExactCFL or ConservativeCFL

  • stop::AbstractSimulationEnd: default stopping criterion of run!

  • output::OutputConfig: output cadence, field selection and run directory

  • io::Laddie.IOState: runtime I/O state: accumulators, next-event times, run directory, log

  • debug::DebugConfig: debug options

  • exec::Laddie.AbstractExecution: how run! advances the model: step by step (KernelAbstractions) or in compiled batches (Reactant)

Convenience constructor for the idealised ISOMIP+ channel geometry (Asay-Davis et al. 2016). Builds the mask and ice draft analytically, then the Grid, Model and a ready-to-run Simulation of it.

Arguments

  • backend: KernelAbstractions backend. Default CPU(); use CUDABackend() for NVIDIA GPU, ROCBackend() for AMD, MetalBackend() for Apple Silicon.
  • nx, ny: interior cell counts in x and y (default 240 × 40).
  • dx, dy: cell size in metres (default 2 km).
  • xgl: grounding-line x-position in metres (default 20 km).
  • xfront: ice-front x-position in metres (default 460 km).
  • z_draft_gl, z_draft_front: ice-draft depth at grounding line and ice front in metres (default −720 m and −200 m).

  • FT: floating-point precision type (default Float64; use Float32 for GPU).
  • params: Params object (default Params(; FT), the ISOMIP+-canonical values).
  • domain_cropping, preprocess: forwarded to Grid.
  • boundary: forwarded to Model.
  • any other keyword (dt, time_stepper, cfl, nu, stop, output, restart, debug) is forwarded to Simulation.

Laddie.run! — Function
run!(sim::Simulation; days, until, verbose) -> Simulation

Advance simulation sim until until is met, an AbstractSimulationEnd measured from the current clock time (default sim.stop; days = 30 is short for until = FixedSimulationEnd(t_end = 30)). The clock is never reset, so successive calls continue the run. Each step is one time_step!; output, diagnostics and restarts are written when due (see Output and restarts), and the call ends with a restart. verbose shows a progress bar. The run warns when the worst-case CFL number exceeds 1 and aborts on non-finite fields.

Returns sim for chaining.

source
Laddie.time_step! — Function
time_step!(sim::Simulation) -> Simulation

Advance sim by one leapfrog time step: advance_leapfrog! → leapfrog_step! (2×dt, which ends each momentum step with clamp_velocities!) → apply_robert_asselin_filter!, then move the clock forward by dt. No I/O, no CFL control, no blow-up check — those belong to run!.

Returns sim.

Laddie.meltstats — Function
meltstats(
    sim::Simulation
) -> NamedTuple{(:max_melt, :mean_melt, :max_speed, :total_melt, :refreezing), <:NTuple{5, Any}}

Melt and speed statistics of the current state of a model or simulation, as a named tuple of CPU scalars:

  • max_melt, mean_melt: maximum and mean net basal melt rate over ice-covered cells (m yr⁻¹)
  • max_speed: maximum speed |u| (m s⁻¹)
  • total_melt: integrated net basal melt (Gt yr⁻¹)
  • refreezing: integrated refreezing (Gt yr⁻¹)

The net basal melt is melt − frazil, freshwater equivalent; total_melt + refreezing is the melting alone. See Melt statistics.

Laddie.to_backend — Function
to_backend(
    sim::Simulation,
    backend
) -> Simulation{M, CL, TS, C, <:Any, E, O, IOS, D, Laddie.NativeExecution} where {M<:Model, CL<:Clock, TS<:AbstractTimeStepper, C<:AbstractCFL, E<:AbstractSimulationEnd, O<:OutputConfig, IOS<:Laddie.IOState, D<:DebugConfig}

Return a new simulation whose model and I/O accumulators live on backend. The clock, time stepper and output configuration are carried over; the original simulation is not modified.

With a ReactantBackend, run! then advances the simulation in compiled batches of steps (requires using Reactant, CUDA); the time series of OutputConfig (tsday) are not available there.

source
to_backend(m::Model, backend) -> Model

Return a new model with all floating-point arrays transferred to backend. The original model is not modified; always assign the result:

using CUDA
model = Model(Grid(mask, z_draft, dx, dy); forcing)
model = to_backend(model, CUDABackend())
sim = Simulation(model)

Prefer passing backend directly to Grid or build_isomip where possible — it avoids the redundant CPU allocation:

sim = build_isomip(CUDABackend(); FT = Float32)

Laddie.ReactantBackend — Type
struct ReactantBackend{F, M, P}

Run a simulation through Reactant.jl: the time step is traced, compiled with XLA and executed in batches of steps, on the GPU or the CPU that Reactant targets. Requires using Reactant, CUDA (CUDA.jl is needed even for the CPU target, since Reactant compiles the kernels through it).

using Laddie, Reactant, CUDA
sim = build_isomip(CPU(); FT = Float32)          # build and bootstrap on the CPU
rsim = to_backend(sim, ReactantBackend())        # move to Reactant
run!(rsim; days = 30)                            # compiled on the first call

With a mesh (a Reactant.Sharding.Mesh) the grid is split over several devices along partition; each split axis must be divisible by its number of devices. Results agree with the KernelAbstractions backends to round-off. See Reactant backend.

Fields

  • fusion::Any: how XLA may fuse the kernels of a step (see the Reactant docs page); :auto picks the measured best

  • mesh::Any: device mesh to shard the grid over, a Reactant.Sharding.Mesh; nothing for one device

  • partition::Any: mesh axis name (or nothing) each grid axis is split along; nothing for the default

Laddie.build_laddie_mask — Function
build_laddie_mask(bed, thickness; rho_ice, rho_sw)

Derive the LADDIE domain mask from BedMachine-style bed elevation bed (m, positive up) and ice thickness (m) on the interior (nx, ny); the result is (nx+2, ny+2), with a border ring of 1.

ValueMeaningCondition
0open oceanthickness ≤ 0 and bed < 0
1landthickness ≤ 0 and bed ≥ 0; border ring
2grounded icethickness > 0 and h_af ≥ 0
3floating shelfthickness > 0 and h_af < 0

with h_af = thickness × rho_ice/rho_sw + bed the height above flotation. Exposed bedrock is land, so a rock island in a shelf is a wall, not an open-ocean sink. Gaps (4) are marked by MarkGapsPreprocess. The default densities (kg m⁻³) are BedMachine's.

source
Laddie.ice_base_depth — Function
ice_base_depth(bed, thickness; rho_ice, rho_sw)

Ice-base depth (m, negative below sea level) from BedMachine-style arrays, as a (nx+2, ny+2) matrix for Grid: -thickness * rho_ice/rho_sw where the ice floats (h_af < 0), bed where it is grounded, 0 elsewhere and on the border ring. Arguments as for build_laddie_mask.

bed_elevation(bed; FT)

Pad a bed-elevation array into the (nx+2, ny+2) format expected by Grid. The one-cell border ring is zeroed; interior values are copied from bed unchanged. Pass the result as Grid(...; z_bed); only the topographic caps of AbstractMaxLayerThickness use it.

Arguments

fill_ocean_holes!(mask::AbstractMatrix{Int64}) -> Int64

Turn enclosed ocean pockets of mask into land (0 → 1): ocean cells not 4-connected to the ocean on the outer ring. Land, not grounded ice, since there is no ice there. Modifies mask and returns the number of cells changed.

Laddie.fill_shelf_holes! — Function
fill_shelf_holes!(mask::AbstractMatrix{Int64}) -> Int64

Turn shelf patches with no 4-connected path to the open ocean into grounded ice (3 → 2): a shelf with no ice front. Call fill_ocean_holes! first, so that enclosed pockets do not count as ocean. Modifies mask and returns the number of cells changed.

Laddie.Params — Type
struct Params{FT, EP<:AbstractEntrainment, MP<:AbstractMelting, CS<:AbstractConvection, FZ<:AbstractFrazilIce, IC<:AbstractIceConduction, EQ<:AbstractEOS, MLT<:AbstractMaxLayerThickness, TB<:AbstractTracerBounds, LV<:AbstractLateralViscosity, LW<:AbstractLaplacianWeights, FP<:AbstractFrontPressure, MA<:AbstractMomentumAdvection, TF<:AbstractTracerForm, MF<:AbstractMomentumForm, CL<:AbstractClosureLevel, CP<:AbstractCoriolisParameter, IS<:AbstractIceSlope, KT<:AbstractKinks}

All physical constants and parameterization choices of a Model, in one immutable, concretely typed struct. Build it with the keyword constructor Params(; ...), which fills in the ISOMIP+-canonical defaults. Time integration is configured on the Simulation, and the boundary conditions in BoundaryConditions.

Rates follow the model's convention: melt and the entrainment rates are freshwater-equivalent layer-thickness rates in m s⁻¹, and δρ is the reduced density contrast (ρ_a − ρ)/ρ₀.

Fields

  • g::Any: gravitational acceleration (m s⁻², default 9.81)

  • C_d::Any: quadratic drag coefficient of the layer against the ice base, momentum equations (–, default 2.5e-3)

  • C_d_top::Any: drag coefficient in the friction velocity u★ that drives melt and entrainment (–, default 1.1e-3)

  • A_h::Any: lateral momentum viscosity under PrescribedLateralViscosity, walls included; also enters HollandEntrainment (m² s⁻¹, default 6)

  • K_h::Any: lateral tracer diffusivity (m² s⁻¹, default 1)

  • H_min::Any: minimum layer thickness, kept by extra entrainment and a final clamp (m, default 1)

  • v_cut::Any: speed cap applied to the velocity after each momentum step (m s⁻¹, default 1.414)

  • u_tide::Any: tidal velocity added in quadrature in the friction velocity (m s⁻¹, default 0.01)

  • rho_freshwater::Any: freshwater density, for the melt mass flux (kg m⁻³, default 1000)

  • rho0_seawater::Any: reference seawater density ρ₀, which scales δρ (kg m⁻³, default 1028)

  • rho_ice::Any: ice density (kg m⁻³, default 910); used by the solver only for the ice thickness of LinearProfileIceConduction, otherwise for conversions by the caller

  • L::Any: latent heat of fusion (J kg⁻¹, default 3.34e5)

  • c_p::Any: specific heat capacity of seawater (J kg⁻¹ K⁻¹, default 3974)

  • c_i::Any: specific heat capacity of ice (J kg⁻¹ K⁻¹, default 2009)

  • l1::Any: liquidus slope in salinity, T_f = l1·S + l2 + l3·z (K psu⁻¹, default -5.73e-2)

  • l2::Any: liquidus offset (°C, default 8.32e-2)

  • l3::Any: liquidus slope in depth (K m⁻¹, default 7.61e-4)

  • H_init::Any: initial layer thickness (m, default 10)

  • dT_init::Any: initial temperature offset from the ambient water (K, default 0)

  • dS_init::Any: initial salinity offset from the ambient water (psu, default -0.1)

  • seconds_per_day::Any: seconds per day, for the day-based simulation and output times (default 86400)

  • seconds_per_year::Any: seconds per year, for rates reported in m yr⁻¹ (default 365.25 × 86400)

  • entrainment::AbstractEntrainment: entrainment scheme, an AbstractEntrainment (default GasparEntrainment(2.5))

  • melting::AbstractMelting: melt scheme, an AbstractMelting (default FixedGamTMelting(1.8e-4))

  • convection::AbstractConvection: convective-instability treatment, an AbstractConvection (default RelaxToAmbientConvection(3600))

  • frazil_ice::AbstractFrazilIce: frazil-ice formation in a supercooled layer, an AbstractFrazilIce (default none)

  • ice_conduction::AbstractIceConduction: heat conduction into the ice at the interface, an AbstractIceConduction (default MeltOnlyIceConduction())

  • equation_of_state::AbstractEOS: equation of state, an AbstractEOS (default LinearEOS())

  • max_layer_thickness::AbstractMaxLayerThickness: upper bound on the layer thickness, an AbstractMaxLayerThickness (default none)

  • tracer_bounds::AbstractTracerBounds: bounds on the layer temperature and salinity, an AbstractTracerBounds (default NoTracerBounds())

  • lateral_viscosity::AbstractLateralViscosity: lateral momentum viscosity, an AbstractLateralViscosity (default constant A_h)

  • laplacian_weights::AbstractLaplacianWeights: time level of the Laplacian thickness weights, an AbstractLaplacianWeights

  • front_pressure::AbstractFrontPressure: ice-front pressure-gradient treatment, an AbstractFrontPressure

  • momentum_advection::AbstractMomentumAdvection: momentum-advection scheme, an AbstractMomentumAdvection (default centred, as in v1.x)

  • tracer_form::AbstractTracerForm: form of the tracer equations, an AbstractTracerForm (default flux form, as in v2)

  • momentum_form::AbstractMomentumForm: form of the momentum equations, an AbstractMomentumForm (default flux form, the transport H U as in LADDIE v2)

  • closure_level::AbstractClosureLevel: time level of u★, the entrainment thickness and the drag speed, an AbstractClosureLevel (default PastClosureLevel())

  • coriolis::AbstractCoriolisParameter: Coriolis parameter, an AbstractCoriolisParameter (default f-plane at -1.37e-4 s⁻¹)

  • ice_slope::AbstractIceSlope: stencil of the ice-base slope, an AbstractIceSlope (default MaskedIceSlope())

  • kinks::AbstractKinks: treatment of the kinks (max/min switches, upwinding, √ at zero), an AbstractKinks (default exact)

Laddie.Params — Method
Params(; FT = Float64, kwargs...)

Keyword constructor of Params; every keyword is a field of the same name (see there for units and defaults), and all scalars and the floating-point fields of the parameterization objects are converted to FT (default Float64). All parameters default to ISOMIP+-canonical values, so Params() is a valid ready-to-use parameter set. Override individual fields as needed:

julia> params = Params(; coriolis = CoriolisParameter0D(0.0), melting = TurbulentGamTMelting(), FT = Float32);

julia> params.melting
TurbulentGamTMelting{Float32}(13.8f0, 2432.0f0, 1.95f-6)

tracer_bounds bounds the layer temperature and salinity inside the active domain after every tracer step; see AbstractTracerBounds for what that costs.

Laddie.BoundaryConditions — Type
struct BoundaryConditions{OB<:AbstractOpenOceanBC, GL<:AbstractSlipAtGL, LB<:AbstractSlipAtLand, GB<:AbstractGapsBC, WA<:AbstractWallAdvection}

The boundary conditions of a Model: what happens at the ice front, at grounding-line and land walls, and in ice-shelf gaps. Pass it as Model(...; boundary = BoundaryConditions(...)). Every condition has a default. The walls default to LADDIE v2's: zero velocity one grid spacing behind every wall in the viscosity (PartialSlipAtGL(1.0), PartialSlipAtLand(1.0)) and no momentum across walls (NoWallAdvection). The other conditions are those of both LADDIE versions.

julia> BoundaryConditions(; land_slip = FreeSlipAtLand(), gaps = ConnectedGapsBC())
BoundaryConditions(open ocean = OutflowOnlyOpenOceanBC, grounding line = PartialSlipAtGL, land = FreeSlipAtLand, gaps = ConnectedGapsBC, wall advection = NoWallAdvection)

julia> BoundaryConditions(; grounding_line_slip = NoSlipAtGL(), land_slip = NoSlipAtLand(),   # LADDIE v1 walls
                          wall_advection = V1WallAdvection())
BoundaryConditions(open ocean = OutflowOnlyOpenOceanBC, grounding line = NoSlipAtGL, land = NoSlipAtLand, gaps = SinkGapsBC, wall advection = V1WallAdvection)

Fields

  • open_ocean::AbstractOpenOceanBC: ice front: OutflowOnlyOpenOceanBC (default), ZeroGradientOpenOceanBC or NoInflowOpenOceanBC

  • grounding_line_slip::AbstractSlipAtGL: grounding-line walls: PartialSlipAtGL (default PartialSlipAtGL(1.0)), NoSlipAtGL or FreeSlipAtGL

  • land_slip::AbstractSlipAtLand: land walls: PartialSlipAtLand (default PartialSlipAtLand(1.0)), NoSlipAtLand or FreeSlipAtLand

  • gaps::AbstractGapsBC: ice-shelf gaps: SinkGapsBC (default), ConnectedGapsBC or LeakyGapsBC

  • wall_advection::AbstractWallAdvection: wall slip in the momentum advection: NoWallAdvection (default), SlipScaledWallAdvection or V1WallAdvection

Laddie.Cache — Type
mutable struct Cache{A<:AbstractMatrix, GamT, Conv2, Frz, PM, Gap}

Pre-allocated diagnostic and scratch fields of a Model, updated in place every time step and read through the model, e.g. model.melt (m s⁻¹), model.entr, model.drho. adv, lap and Hq are work arrays shared by the stepped equations; diag is free for host-side diagnostics.

Fields

  • melt::AbstractMatrix: basal melt rate (m s⁻¹)

  • Tb::AbstractMatrix: temperature at the ice–ocean interface (°C)

  • Ta::AbstractMatrix: ambient temperature at the layer base (°C)

  • Sa::AbstractMatrix: ambient salinity at the layer base (psu)

  • drho::AbstractMatrix: reduced density contrast with the ambient water (dimensionless)

  • ustar::AbstractMatrix: friction velocity at the ice base (m s⁻¹)

  • entr::AbstractMatrix: entrainment rate, the positive part of the signed rate ė (m s⁻¹)

  • detr::AbstractMatrix: detrainment rate, the capped negative part of ė (m s⁻¹)

  • ent2::AbstractMatrix: extra entrainment that keeps H ≥ H_min after the thickness step (m s⁻¹)

  • nentr::AbstractMatrix: net entrainment entr + ent2 - detr of the thickness and tracer equations (m s⁻¹)

  • detr_cap::AbstractMatrix: detrainment of layer water that keeps H under max_layer_thickness after the thickness step (m s⁻¹)

  • convective_instability::AbstractMatrix: convective-instability indicator: 1 where drho < 0 was corrected

  • convH::AbstractMatrix: upwind advection term of the thickness equation (m s⁻¹)

  • dHdt::AbstractMatrix: thickness tendency of the current step (m s⁻¹)

  • frazil::Any: frazil-ice formation rate under RelaxedFrazilIce (m s⁻¹, freshwater equivalent; a field), else zero as a scalar

  • gamT::Any: turbulent heat transfer velocity (m s⁻¹): a field, or a scalar under FixedGamTMelting

  • gap_heat::Any: surface heat loss (1 − α) Q in gap cells under LeakyGapsBC (W m⁻², a field, fixed at build), else zero as a scalar

  • lap::AbstractMatrix: Laplacian term of the equation being stepped (work buffer)

Three leapfrog levels (past, present, future) for a prognostic field located at staggering position (LX, LY) on the C-grid.

Forcing

A model is driven by a CavityForcing: an ocean forcing supplying the ambient T/S, and an ice forcing supplying the ice temperature T_ice_farfield (the temperature of the ice above the basal boundary layer, typically the surface temperature; see PrescribedIceForcing). Passing an ocean forcing on its own to Model is shorthand for pairing it with a uniform PrescribedIceForcing(-25.0).

Laddie.CavityForcing — Type
struct CavityForcing{O<:AbstractOceanForcing, I<:AbstractIceForcing}

The complete external forcing of a cavity: an ocean forcing and an ice forcing.

Model takes one of these. Passing a bare ocean forcing is shorthand for CavityForcing(ocean), which pairs it with a uniform PrescribedIceForcing(-25.0).

Ocean

The ocean forcing types are described in Ocean forcing.

From a 3D ocean field

Ocean models that force ice-sheet models mostly have no ice-shelf cavities. front_ocean_forcing gives every cavity cell the water column at the ice front that feeds it, cut at that front's seabed, or with FrontBlend a blend of the columns of the closest stretch of front; regrid_ocean and fill_ocean! bring a coarse ocean grid onto the model's cells.

Laddie.front_ocean_forcing — Function
front_ocean_forcing(T, S, z, mask; depth = nothing, blend = nothing, cut = true, FT = Float64)

Ambient forcing from outside the ice fronts only, as an ocean model without cavities gives it: every cavity cell of mask takes the water column of its open-ocean source (front_sources), extended flat below its deepest water.

  • T, S: (nx, ny, nz) on the uniform depths z, for the full domain of mask, NaN where there is no water.
  • depth: bed elevation (m, size of mask); the deepest open-ocean neighbour of a front cell wins (without it, the column with the most water).
  • cut: cut each source column at its own seabed first (needs depth), so that ocean data extrapolated below the seabed is not read.
  • blend: a FrontBlend, to blend the columns of nearby fronts.

Returns a PerBasinOceanForcing1D with one profile per source column (and per blended cell); cells outside the cavities take the nearest cavity cell's.

source
Laddie.FrontBlend — Type
FrontBlend(front_length = 64e3; dx)

Blend the front columns that force a cavity cell, for front_ocean_forcing: each cavity cell takes the weighted mean of the source columns of its n = front_length / dx closest sources (distance through the cavity, as in front_sources). Source $k$ at distance $d_k$ weighs $d_{n+1} - d_k$, normalised, so a source enters and leaves a blend at zero weight and the forcing has no steps where the nearest front changes. front_length and dx in m; the 64 km default is calibrated in the front-blend devnote.

source
Laddie.front_sources — Function
front_sources(mask; wet = trues(size(mask)), depth = nothing) -> (source, lost)

The open-ocean cell whose water column forces each cavity cell, on a Laddie mask (border ring included). Open ocean is the 0 cells connected to the domain edge; the cavity is the rest of the floating ice (3), gaps (4) and enclosed water. A front cell takes its deepest wet open-ocean neighbour (lowest depth); every other cavity cell takes the source of the front nearest through the cavity (8-neighbour chamfer distance), or, if none reaches it, in a straight line.

Returns the linear index of each cavity cell's source (0 elsewhere), and the number of cells that took a straight line.

source
Laddie.nearest_seed — Function
nearest_seed(labels) -> (label, d2)

For every cell of the matrix labels, the label of the nearest seed (a cell with labels > 0) and the squared distance to it in cells², by exact Euclidean distance (Felzenszwalb & Huttenlocher 2012: the 1D lower-envelope transform along the columns, then along the rows). Seeds keep their own label. With no seed at all, every label is 0 and every distance Inf.

source
Laddie.regrid_ocean — Function
regrid_ocean(T, S, x, y, px, py) -> (; T, S)

Bilinear interpolation of the 3D ocean fields T, S ((length(x), length(y), nz) on the ascending axes x, y, NaN or missing where there is no water) to the points px × py, level by level, flat beyond the axes. Missing values are left out, the weights renormalised over the valid source cells; a point with no valid neighbour is NaN. For the cell centres of a full domain, pass its axes with the border ring (Grid takes x, y that way).

Use the result in front_ocean_forcing, or fill it with fill_ocean! for an OceanForcing2D.

source
Laddie.fill_ocean! — Function
fill_ocean!(T, S) -> (T, S)

Fill the NaNs of the 3D ocean fields T, S (e.g. from regrid_ocean) so that every column is complete: each column extends flat beyond its own water (a level takes the value of the nearest level with one), and a column with no water takes the nearest column with water in both, by exact Euclidean distance.
