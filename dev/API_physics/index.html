Entrainment

Laddie.AbstractEntrainment — Type

Abstract supertype for the entrainment parameterisation — the rate at which ambient water is mixed into the layer. Pass a concrete instance as Params(; entrainment = ...): LambertEntrainment (the default), GasparEntrainment or HollandEntrainment.

source
Laddie.LambertEntrainment — Type
struct LambertEntrainment{FT} <: AbstractEntrainment

Buoyancy-flux-driven entrainment as implemented in the reference LADDIE model (Lambert et al. 2023; Gaspar 1988; Gladish et al. 2012). This is the form verified bit-for-bit against the Python reference and is the default.

The net entrainment solves the layer mechanical-energy balance for $\dot{e}$,

\[\dot{e} = \frac{2\mu}{g}\,\frac{u_\star^3}{D\, \delta \rho} - \frac{\delta \rho_b}{\delta \rho}\,\dot{m},\]

with a single power of D and a factor 2 \mu in the production term. This differs from a literal reading of Eq. 14 (see GasparEntrainment and docs/src/equations.md).

This is also what LADDIE v2 calls 'Gaspar1988' (laddie_physics.f90, compute_entrainment); Laddie.jl's GasparEntrainment is a different form.

Select via Params(; entrainment = LambertEntrainment(2.5)).

Fields

  • mu::Any: dimensionless efficiency parameter (ISOMIP+ default 2.5)
source
Laddie.GasparEntrainment — Type
struct GasparEntrainment{FT} <: AbstractEntrainment

Buoyancy-flux-driven entrainment as the literal reading of Eq. 14 of Lambert et al. (2023), $D^2 g_b' \dot{m} + D^2 g_a' \dot{e} = \mu u_\star^3$, solved for $\dot{e}$:

\[\dot{e} = \frac{\mu}{g}\,\frac{u_\star^3}{D^2\,\delta\rho} - \frac{\delta\rho_b}{\delta\rho}\,\dot{m}.\]

Note the $D^2$ in the denominator and the factor $\mu$ (not $2\mu$). This is not the form the reference LADDIE actually integrates — for that, use the default LambertEntrainment. The melt-buoyancy/detrainment term $-(\delta\rho_b/\delta\rho)\,\dot{m}$ is identical in both.

Select via Params(; entrainment = GasparEntrainment(2.5)).

Fields

  • mu::Any: dimensionless efficiency parameter (ISOMIP+ default 2.5)
source
Laddie.HollandEntrainment — Type
struct HollandEntrainment{FT} <: AbstractEntrainment

Shear-driven entrainment following Holland & Jenkins (1999):

\[\dot{e} = c_l \, \frac{K_h}{A_h^2} \sqrt{\max\left(0,\; |\mathbf{u}|^2 - g\,\delta\rho\,\frac{K_h}{A_h}\,D\right)},\]

with $|\mathbf{u}|$ the speed at the T-point, $\delta\rho$ the reduced density contrast and $K_h$, $A_h$ the lateral diffusivity and viscosity of Params. There is no detrainment.

Select via Params(; entrainment = HollandEntrainment(0.01775)).

Fields

  • cl::Any: entrainment coefficient (default 0.01775)

  • gamTfix::Any: heat transfer coefficient, dimensionless in the reference formulation (ISOMIP+ default 1.8e-4)
source
Laddie.TurbulentGamTMelting — Type
struct TurbulentGamTMelting{FT} <: AbstractMelting

Three-equation melt parameterisation with turbulence-dependent transfer coefficients $\gamma_T$ and $\gamma_S$ via the log-layer formulation (Holland & Jenkins 1999; Lambert et al. 2023, Eqs. 11–12):

\[\begin{aligned} c_p \, \gamma_T \,(T - T_b) &= \dot{m} \, L + \dot{m} \, c_i \, (T_b - T_i) \\ \gamma_S \, (S - S_b) &= \dot{m} \, S_b \\ T_b &= \lambda_1 \, S_b + \lambda_2 + \lambda_3 \, z_b \end{aligned}\]

The turbulent heat exchange coefficients are determined by:

\[\begin{aligned} \gamma_T &= \frac{u_\star}{2.12 \, \log \frac{u_\star D}{\nu_0} + 12.5 \, \mathrm{Pr}^{2/3} - 8.68} \\ \gamma_S &= \frac{u_\star}{2.12 \, \log \frac{u_\star D}{\nu_0} + 12.5 \, \mathrm{Sc}^{2/3} - 8.68} \end{aligned}\]

This results in a quadratic equation for the melt rate $\dot{m}$.

The log term is floored at zero, i.e. $u_\star D/\nu_0$ is taken as at least 1. Below that the layer is thinner than its own viscous sublayer, where the log law does not hold, and the unbounded log would drive the denominator through zero and give a negative or huge $\gamma$. The floor never binds at the default parameters: Params.u_tide and Params.D_min keep $u_\star D/\nu_0$ above about 170. With the floor, both denominators stay positive when $12.5 \, \mathrm{Pr}^{2/3} > 8.68$ (and likewise for Sc), which the constructor checks.

Example

Params(; melting = TurbulentGamTMelting(13.8, 2432.0, 1.95e-6))

Fields

  • Pr::Any: Prandtl number (default 13.8); must exceed (8.68/12.5)^1.5 ≈ 0.58

  • Sc::Any: Schmidt number (default 2432.0); same bound as Pr

  • nu0::Any: molecular kinematic viscosity (m² s⁻¹, default 1.95e-6); must be positive

source
Laddie.UStarGamTMelting — Type
struct UStarGamTMelting{FT} <: AbstractMelting

Three-equation ice–ocean melt parameterisation (the equations are given under TurbulentGamTMelting) with transfer coefficients proportional to the friction velocity (Jenkins et al. 2010):

\[\gamma_T = \Gamma_T \, u_\star, \qquad \gamma_S = \gamma_T / 35 .\]

This is LADDIE v2's 'uniform' option, which is also what the ISOMIP+ protocol tunes (Asay-Davis et al. 2016). Jesse et al. (2026) use $\Gamma_T = 3 \times 10^{-2}$.

Example

Params(; melting = UStarGamTMelting(3.0e-2))

Fields

  • Gamma_T::Any: dimensionless heat transfer coefficient (default 3.0e-2)
source
Laddie.PrescribedMelting — Type
struct PrescribedMelting{M} <: AbstractMelting

Prescribed melt rate, $\dot{m} = \dot{m}_0$, applied on ice-covered cells only (gap cells never melt).

melt is in m yr⁻¹ of freshwater — the same units as the model's melt output — and may be a scalar or a full-domain matrix the same size as the mask passed to Grid; Model crops a matrix alongside the mask. Negative values freeze.

The melt still acts on the layer as in the three-equation model, so a prescribed melt rate cools and freshens the plume consistently:

  • the interface temperature is the local freezing point, $T_b = \lambda_1 S + \lambda_2 + \lambda_3 z_b$;
  • the layer loses the heat that melting requires, $\gamma_T (T - T_b) = \dot{m}\,(L - c_i (T_i - T_b)) / c_p$, with the equivalent $\gamma_T$ reported as m.gamT;
  • the friction velocity $u_\star$ is computed as usual, since entrainment needs it.

Example

Params(; melting = PrescribedMelting(10.0))          # uniform 10 m/yr
Params(; melting = PrescribedMelting(melt_matrix))   # 2D, same size as `mask`

Fields

  • melt::Any: prescribed melt rate (m yr⁻¹ freshwater), a scalar or a matrix the size of mask (default 0)

source
Laddie.ZeroGradientInflow — Type
struct ZeroGradientInflow <: AbstractOpenOceanBC

Open-boundary condition at the ice front: zero-gradient extrapolation of all fields, with inflow from the ambient ocean permitted.

source
Laddie.NoInflow — Type
struct NoInflow <: AbstractOpenOceanBC

Open-boundary condition at the ice front: no inflow of layer properties. Where the flow enters the domain through an ice-front face, the thickness and tracer fluxes carry the (zero) value stored in the open-ocean cell instead of the zero-gradient extrapolation of ZeroGradientInflow, so no volume, heat or salt is advected in. The velocities themselves are not clipped, and momentum advection is unaffected.

Grounding line

Laddie.AbstractGroundingLineBC — Type

Abstract supertype for the momentum boundary condition at grounding-line walls (mask value 2). Pass a concrete instance as BoundaryConditions(; grounding_line = ...): NoSlipGL (the default), FreeSlipGL or PartialSlipGL.

Walls bordering exposed rock are governed separately by AbstractLandBC.

source
Laddie.NoSlipGL — Type
struct NoSlipGL <: AbstractGroundingLineBC

No-slip momentum boundary condition at the grounding line (the default): the tangential velocity vanishes at walls bordering grounded ice (mask value 2). Implemented as a slip factor of 2 on grounding-line faces. Land walls (mask value 1) are governed independently by BoundaryConditions.land.

Motivated by LADDIE v2.0 (Lambert et al., in review, 2026), where a no-slip grounding-line condition improves melt patterns near the grounding line compared to observations.

Select via BoundaryConditions(; grounding_line = NoSlipGL()) (the default).

source
Laddie.FreeSlipGL — Type
struct FreeSlipGL <: AbstractGroundingLineBC

Free-slip momentum boundary condition at the grounding line: slip factor 0 at walls bordering grounded ice, the free-slip end of the Python LADDIE convention (no wall drag beyond the zero velocity stored in the wall cell).

Select via BoundaryConditions(; grounding_line = FreeSlipGL()).

source
Laddie.PartialSlipGL — Type
struct PartialSlipGL{FT} <: AbstractGroundingLineBC

Partial-slip momentum boundary condition at the grounding line, with a slip factor between 0 (free slip) and 2 (no slip).

Python LADDIE v1.x applies one factor, slip = 1, to every wall; reproduce it with BoundaryConditions(; grounding_line = PartialSlipGL(1.0), land = PartialSlipLand(1.0)).

Select via BoundaryConditions(; grounding_line = PartialSlipGL(1.0)).

Fields

  • factor::Any: slip factor, from 0 (free slip) to 2 (no slip)

Laddie.AbstractLandBC — Type

Abstract supertype for the momentum boundary condition at land walls (mask value 1: exposed bedrock, islands, and the outer border ring). Pass a concrete instance as BoundaryConditions(; land = ...): NoSlipLand (the default), FreeSlipLand or PartialSlipLand.

The grounding line is governed separately by AbstractGroundingLineBC; at a coastline corner whose stencil touches both grounded ice and exposed rock, the grounding-line condition takes precedence (the land wall indicators exclude faces already flagged as grounding line), so each wall face gets exactly one slip factor.

Wall momentum advection

Laddie.AbstractWallAdvection — Type

Abstract supertype for how the wall slip condition enters the advective term of the momentum equations, as opposed to the viscous wall drag. Pass a concrete instance as BoundaryConditions(; wall_advection = ...): SlipScaledWallAdvection (the default) or NoWallAdvection.

The slip factor of AbstractGroundingLineBC / AbstractLandBC always scales the viscous wall drag; this choice decides whether it also scales the momentum carried across a wall face by the upwind advection.

source
Laddie.SlipScaledWallAdvection — Type
struct SlipScaledWallAdvection <: AbstractWallAdvection

Apply the wall slip factor to the upwind momentum advection as well as to the viscous wall drag, as Python LADDIE v1.x does (the default): the tangential momentum flux across a wall face is formed with a ghost velocity (1 - slip)·u, so free slip (0) leaves the flux at its interior value, no slip (2) reverses it.

Select via BoundaryConditions(; wall_advection = SlipScaledWallAdvection()) (the default).

source
Laddie.NoWallAdvection — Type
struct NoWallAdvection <: AbstractWallAdvection

Carry no momentum across walls: the upwind momentum advection sees a slip factor of 0 at grounding-line and land faces whatever the wall condition is, while the viscous wall drag keeps the factor of AbstractGroundingLineBC / AbstractLandBC.

This is what LADDIE v2 does: both of its momentum-advection schemes skip grounded neighbours outright (laddie_velocity.f90, "No flux across grounding line"), and no slip enters only through compute_viscUV. Combine it with NoSlipGL / NoSlipLand to reproduce v2's walls; with free slip it is a no-op, since the factor is 0 in both terms.

Select via BoundaryConditions(; wall_advection = NoWallAdvection()).

source

Momentum advection

Laddie.AbstractMomentumAdvection — Type
abstract type AbstractMomentumAdvection

Abstract supertype for the momentum-advection scheme — how the momentum carried through a face of a velocity control volume is evaluated.

To use this within a simulation, pass a concrete instance as Params(; momentum_advection = ...): CentredMomentumAdvection (the default) or UpstreamMomentumAdvection.

Tracer advection is always upwind and is unaffected.

source
Laddie.CentredMomentumAdvection — Type
struct CentredMomentumAdvection <: AbstractMomentumAdvection

Evaluate the advected momentum as the average of the two velocities either side of the face (the default), as Python LADDIE v1.x does: the east face of a U-control volume carries D̄·ū·ū with ū = (U[i] + U[i+1])/2, and likewise for the other faces. Centred differencing adds no numerical viscosity of its own.

Select via Params(; momentum_advection = CentredMomentumAdvection()) (the default).

source
Laddie.UpstreamMomentumAdvection — Type
struct UpstreamMomentumAdvection <: AbstractMomentumAdvection

Flux-form donor-cell (first-order upwind) momentum advection, as in LADDIE v2.

Each face of a velocity control volume carries the mass flux of the thickness equation — the same donor-cell D·u the tracer advection uses, gated by umask/vmask — averaged onto that face from the two adjacent T-cell faces. The momentum it carries is the velocity on the upstream side of the face. Both the thickness and the velocity are therefore taken from the donor side, as v2 does (Hstar_b(ti) vs Hstar_b(tj) in compute_divQUV_upstream / compute_divQUV_fesom, laddie_velocity.f90).

v2's two schemes, 'upstream' and 'fesom', differ only in how the face-normal velocity is built from the mesh's staggered fields — a triangle-vs-vertex degree-of-freedom question that does not arise on a C-grid, where the face velocity is the one used here.

Two consequences follow from building the fluxes this way:

  • Walls carry no momentum, because they carry no mass (umask/vmask are zero there). That is v2's "No flux across grounding line", so AbstractWallAdvection has no effect under this scheme and the wall slip factor acts through the viscosity alone, again as in v2.
  • An inflow face at the ice front carries the cell's own thickness and velocity (zero gradient), matching the thickness equation's ZeroGradientInflow.

First-order upwinding is dissipative: its implicit numerical viscosity is of order |u|·Δ/2, which at 1 km and 0.1 m s⁻¹ is ≈ 50 m² s⁻¹, far above a typical Params.A_h. Expect a less energetic layer than under CentredMomentumAdvection.

Select via Params(; momentum_advection = UpstreamMomentumAdvection()).

Lateral viscosity

Laddie.AbstractLateralViscosity — Type

Abstract supertype for lateral (horizontal) momentum viscosity closures. Pass a concrete instance as Params(; lateral_viscosity = ...): PrescribedLateralViscosity (constant coefficient, the default) or NonlinearLateralViscosity (shear-scaled, as in LADDIE v2).

Tracer diffusivity Params.K_h is always a constant and is unaffected.

source
Laddie.PrescribedLateralViscosity — Type
struct PrescribedLateralViscosity <: AbstractLateralViscosity

Constant-coefficient Laplacian lateral viscosity (the default): the diffusive flux at every interior face is Params.A_h * ΔU / dy (or ΔV / dx), i.e. a plain Laplacian with a single global coefficient, matching Python LADDIE v1.x.

Grounding-line/land wall friction also scales with Params.A_h, unaffected by the choice of lateral_viscosity — see NonlinearLateralViscosity.

Select via Params(; lateral_viscosity = PrescribedLateralViscosity()) (the default).

source
Laddie.NonlinearLateralViscosity — Type
struct NonlinearLateralViscosity{FT} <: AbstractLateralViscosity

Shear-scaled lateral viscosity, as used by the reference LADDIE v2 Fortran implementation (laddie_velocity.f90:260). Instead of a constant coefficient, the viscosity at each interior face is

\[A_h^{\mathrm{eff}} = \frac{C_{\mathrm{visc}}}{100}\,\Delta\,\lVert\delta\mathbf{u}\rVert,\]

with Δ the grid spacing across that face (dx for east/west faces, dy for north/south) and $\lVert\delta\mathbf{u}\rVert = \sqrt{\delta U^2 + \delta V^2}$ the magnitude of the full velocity-difference vector across it — the reference's dUabs, so one isotropic coefficient serves both momentum components on a face. The flux of each component then goes as $\lVert\delta\mathbf{u}\rVert\,\delta U$. This is a Smagorinsky-type closure — near-zero viscosity in smooth flow, large viscosity where shear is strong — rather than the plain Laplacian of PrescribedLateralViscosity.

C_visc/100 plays the role of a squared Smagorinsky constant, so the default corresponds to Cs ≈ 0.32.

Because Δ is supplied internally, C_visc is resolution-independent and directly comparable to the reference's config value. It is not comparable to Params.A_h, which is a diffusivity in m² s⁻¹.

Grounding-line/land wall friction is not affected by this choice: the reference keeps its border term linear in the viscosity coefficient even under this scheme (laddie_velocity.f90:249-254), and Laddie.jl mirrors that by always scaling the grounding-line/land wall-drag terms with the global Params.A_h, never with C_visc. Wall slip itself (free-slip vs no-slip) is controlled independently by BoundaryConditions.grounding_line / .land.

C-grid staggering

The reference collocates U and V at triangle centres, so dUabs is a direct difference. On Laddie.jl's staggered C-grid the cross-component must first be interpolated onto this component's points; the same 4-point average the quadratic-drag term uses for the speed magnitude is applied (ip_half(jm_half(V)) for the U equation, jp_half(im_half(U)) for V).

Select via Params(; lateral_viscosity = NonlinearLateralViscosity(10.0)).

Fields

  • C_visc::Any: dimensionless coefficient, the reference C%laddie_viscosity (default 10.0, its MISMIP+ value; the Antarctic test config uses 0.1)
source

Laplacian thickness weights

Laddie.AbstractLaplacianWeights — Type

Abstract supertype for the time level of the layer thickness D that weights all lateral Laplacians (tracer diffusion and momentum viscosity). Pass a concrete instance as Params(; laplacian_weights = ...): PresentLaplacianWeights (the default) or PastLaplacianWeights.

The diffused field itself is always taken at the lagged level past, as leapfrog stability requires; this choice only concerns the thickness that multiplies it. On the Crosson–Dotson validation case the two options give the same mean melt to 0.01 % and differ locally by at most 1.4 m in D.

source
Laddie.PresentLaplacianWeights — Type
struct PresentLaplacianWeights <: AbstractLaplacianWeights

Weight the Laplacians with D.present (the default).

source
Laddie.PastLaplacianWeights — Type
struct PastLaplacianWeights <: AbstractLaplacianWeights

Weight the Laplacians with the lagged, filtered D.past, so the thickness weight sits on the same time level as the diffused field. This is what the Python LADDIE v1.x code does.

Ice-front pressure gradient

Laddie.AbstractFrontPressure — Type

Abstract supertype for the treatment of the layer-thickness-gradient part of the pressure-gradient force at one-sided faces — the ice front, and the edges of a gap demoted to ocean by SinkGapsBC. Pass a concrete instance as Params(; front_pressure = ...): FullDepthGradient (Python LADDIE v1.x, the default) or TruncatedDepthGradient (LADDIE v2).

The grounding line is unaffected either way — no momentum equation is solved there.

source
Laddie.FullDepthGradient — Type
struct FullDepthGradient <: AbstractFrontPressure

Keep the layer-thickness-gradient part of the pressure-gradient force at one-sided faces — the ice front, and the edges of a gap demoted to ocean by SinkGapsBC — evaluating it as (D_neighbour - D)/Δ with the neighbour's stored thickness, which masking pins to 0 there. The term is thus a full one-sided gradient, as if D fell to zero across one grid cell.

This is what Python LADDIE v1.x does (integrate.py, -g·ip_t(Ddrho)·(Dxm1 - D)/dx with Dxm1 = roll(D*tmask)), so it is the default and the setting under which Laddie.jl reproduces the Python reference.

Select via Params(; front_pressure = FullDepthGradient()) (the default).

See also TruncatedDepthGradient.

source
Laddie.TruncatedDepthGradient — Type
struct TruncatedDepthGradient <: AbstractFrontPressure

Drop the layer-thickness-gradient part of the pressure-gradient force at one-sided faces — the ice front, and the edges of a gap demoted to ocean by SinkGapsBC — keeping only the ice-base-slope and density-gradient parts there.

This is what the LADDIE v2 Fortran reference does at calving-front faces (laddie_velocity.f90:118-126, IF (mask_cf_b .OR. mask_gl_b) ... assume dH/dx = 0). It avoids treating a masked neighbour's stored D = 0 as a real thickness: under FullDepthGradient that term is roughly 150× larger at the ice front than in the interior on a warm ISOMIP+ run.

Neither choice affects the grounding line, where the velocity masks are zero and no momentum equation is solved at all.

Select via Params(; front_pressure = TruncatedDepthGradient()).

source

Shelf gaps

Laddie.AbstractGapsBC — Type

Abstract supertype for the treatment of ice-shelf gaps — ice-free cells inside the shelf domain, marked 4 in the mask. Pass a concrete instance as BoundaryConditions(; gaps = ...): SinkGapsBC (the default, gaps act as sinks) or ConnectedGapsBC (gaps stay dynamically connected).

source
Laddie.SinkGapsBC — Type
struct SinkGapsBC <: AbstractGapsBC

Treat ice-shelf gaps — ice-free cells inside the ice-shelf domain, marked 4 in the domain mask — as sinks of the meltwater layer (the default, and the behaviour of LADDIE v1.x). Gap cells are demoted to open ocean (0) at model construction, so a meltwater current reaching a gap loses its heat and momentum to the ambient ocean exactly as it would at the calving front, and cannot drive melting further downstream.

Select via BoundaryConditions(; gaps = SinkGapsBC()) (the default).

See also ConnectedGapsBC.

source
Laddie.ConnectedGapsBC — Type
struct ConnectedGapsBC <: AbstractGapsBC

Treat ice-shelf gaps as dynamically connected: the meltwater layer keeps being integrated across ice-free cells inside the ice-shelf domain, so heat and momentum are advected downstream and can drive melting on the far side of the gap. No melting occurs within a gap itself — there is no glacial ice to melt — so no meltwater volume or buoyancy is added there.

Gap cells are those marked 4 in the domain mask. Mark them either directly (a coupled ice-sheet driver knows its own reference geometry) or from a reference ice footprint with MarkGapsPreprocess in the preprocess list of Grid. This boundary condition only decides what happens in the cells so marked.

Motivated by Jesse et al. (2026, https://doi.org/10.5194/egusphere-2026-4237), who show that the choice between this treatment and SinkGapsBC can alter coupled ice-volume loss by an amount comparable to 1 °C of ocean warming. The two are deliberate end-members; reality lies somewhere between them.

Example

boundary = BoundaryConditions(; gaps = ConnectedGapsBC())
Model(Grid(mask, z_draft, dx, dy); forcing, boundary)   # gaps already marked as 4
grid = Grid(mask, z_draft, dx, dy; preprocess = [MarkGapsPreprocess(refgeo_H)])
Model(grid; forcing, boundary)                          # gaps from a footprint

Maximum layer thickness

Laddie.AbstractMaxLayerThickness — Type

Abstract supertype for the upper bound applied to the layer thickness D after each step. Pass a concrete instance as Params(; max_layer_thickness = ...): NoMaxLayerThickness (the default), TopographicMaxLayerThickness, AbsoluteMaxLayerThickness, or RelativeMaxLayerThickness.

Every bound here is corrective, and that costs more than it looks

All of these clamp D after the thickness step, discarding volume while leaving the momentum and tracer content of the layer untouched. On a real cavity that acts as a mass sink wherever it binds, and the damage is not local: capping a Crosson–Dotson run (see the example page) at the water column collapsed the mean melt rate from 9.9 to 1.1 m yr⁻¹ — including in cells where the cap never binds, because the plume that feeds them no longer develops.

Neither reference bounds D this way. Python LADDIE v1 has no upper bound at all (its maxD = 3000 m never binds), and LADDIE v2 folds a fixed Hmax into the entrainment before the step, so the integration lands in range by itself. Prefer the default, and reach for a cap only as a stability stopgap on a run that is already misbehaving.

source
Laddie.NoMaxLayerThickness — Type
struct NoMaxLayerThickness <: AbstractMaxLayerThickness

Leave the layer thickness unbounded from above (the default): D is set by the volume budget alone, exactly as in Python LADDIE v1, and only the D_min floor is applied after the step.

The layer is then free to exceed the local water column where the budget takes it there — as it does in the published Crosson–Dotson run, in 10 % of the shelf cells. That is a known limitation of a one-layer model, and it is not worth fixing with a corrective clamp; see the warning on AbstractMaxLayerThickness.

Select via Params(; max_layer_thickness = NoMaxLayerThickness()) (the default).

source
Laddie.TopographicMaxLayerThickness — Type
struct TopographicMaxLayerThickness <: AbstractMaxLayerThickness

Cap the layer thickness at the local water-column depth, D <= z_draft - z_bed.

This bound is only meaningful when a bed elevation was given to Grid (z_bed); without one the bed is -Inf, the cap is +Inf and D is unbounded from above. Read the warning on AbstractMaxLayerThickness before selecting it: on a real cavity this cap can suppress melt by an order of magnitude.

Select via Params(; max_layer_thickness = TopographicMaxLayerThickness()).

source
Laddie.AbsoluteMaxLayerThickness — Type
struct AbsoluteMaxLayerThickness{FT} <: AbstractMaxLayerThickness

Cap the layer thickness at a fixed value, D <= D_max, independent of bathymetry: the cap is the same everywhere, whether or not a bed elevation was given. Read the warning on AbstractMaxLayerThickness first.

Select via Params(; max_layer_thickness = AbsoluteMaxLayerThickness(100.0)).

See also NoMaxLayerThickness (the default) and RelativeMaxLayerThickness.

Fields

  • D_max::Any: maximum layer thickness (m, default 100; converted to the model precision by Params)

Laddie.RelativeMaxLayerThickness — Type
struct RelativeMaxLayerThickness{FT} <: AbstractMaxLayerThickness

Cap the layer thickness at a fraction of the local water-column depth, D <= f_D_max * (z_draft - z_bed), leaving some ambient column beneath the plume. Like TopographicMaxLayerThickness this only bites when a bed elevation z_bed was given to Grid.

Select via Params(; max_layer_thickness = RelativeMaxLayerThickness(0.8)).

Fields

  • f_D_max::Any: fraction of the local water column (default 4/5)

source
Laddie.AdaptiveDt — Type
struct AdaptiveDt{FT, I} <: AbstractTimeStepper

Predictive CFL-limited adaptive time stepping. Every ncheck steps the advective–gravity-wave CFL number is measured and dt is nudged toward the step that would hit cfl_target:

factor = (cfl_target / cfl)^q

Because the CFL number is linear in dt, q = 1 would land exactly on the target if the flow did not change in the meantime; q < 1 under-corrects (smoother, less oscillatory), q > 1 over-corrects. The adjustment is asymmetric and predictive — it never rejects a step:

  • above target (cfl > cfl_target) → shrink immediately by factor;
  • well below target (cfl < grow_hyst * cfl_target) → grow by factor, but no more than max_growth per adjustment;
  • in between → hold (hysteresis band keeps changes rare, which matters because each change re-bootstraps the leapfrog).

Select via Simulation(model; tstep = AdaptiveDt()); override fields as needed, e.g. AdaptiveDt(; cfl_target = 0.4, ncheck = 10).

Fields

  • cfl_target::Any: CFL setpoint the controller aims for (default 0.3)

  • q::Any: response exponent: 1 is CFL-exact, < 1 damps, > 1 overshoots (default 1.0)

  • max_growth::Any: largest dt increase per adjustment, e.g. 1.1 = +10 % (default 1.1)

  • grow_hyst::Any: grow only when cfl < grow_hyst * cfl_target (default 0.8)

  • ncheck::Any: steps between CFL checks (default 20)

  • dtmin::Any: lower clamp on dt (s, default 1.0)

  • dtmax::Any: upper clamp on dt (s, default 1000.0)

Laddie.ExactCFL — Type
struct ExactCFL <: AbstractCFL

Per-cell CFL: interpolates U and V to T-points, computes the CFL at every active cell, and returns the maximum (the default). Tighter than ConservativeCFL at the cost of one kernel pass.

Laddie.ConservativeCFL — Type
struct ConservativeCFL <: AbstractCFL

Conservative CFL estimate: takes max|U|, max|V|, and max c independently over the active domain, then adds them. This overestimates the true CFL (the worst velocity and worst wave speed rarely occur at the same cell) but avoids a per-cell kernel pass.

Laddie.SteadyStateEnd — Type
struct SteadyStateEnd{T} <: AbstractSimulationEnd

Stop early once the cavity reaches a quasi-steady state, or after t_end days, whichever comes first. Steadiness is detected when the relative change in the domain-mean basal melt rate (over floating ice) between successive diagnostic samples falls below tol:

\[|\bar{m}_{k+1} - \bar{m}_k| / |\bar{m}_k| < \mathrm{tol}\]

tol is dimensionless, so it means the same thing in a warm cavity (melt of order 100 m yr⁻¹) and a cold one (order 1 m yr⁻¹). Samples are taken once per simulated day (not every step), which is cheap, robust to the leapfrog computational mode, and independent of the run length. t_end is a safety cap on the duration of the run! call.

Select via run!(sim; until = SteadyStateEnd(tol = 1e-3, t_end = 365.0)).

Fields

  • tol::Any: relative change in the mean melt rate between daily samples below which the run stops (default 1e-3)

  • t_end::Any: cap on the duration of the run! call (days, default 365)

Laddie.CoriolisParameter2D — Type
struct CoriolisParameter2D{L} <: AbstractCoriolisParameter

Coriolis parameter from latitude, $f = 2Ω\sin φ$.

lat is in degrees north (negative in the Southern Hemisphere) and may be

  • a scalar — still an f-plane, but stated geographically rather than as a raw frequency. The default reproduces CoriolisParameter0D's default exactly, so swapping one for the other changes nothing until lat is set.
  • a full-domain matrix the same size as mask — a genuine β-plane. Model crops it alongside the mask, so m.f is always a grid-shaped field.

Across the Antarctic shelves f runs from −1.32e-4 at 65 °S to −1.44e-4 at 80 °S, roughly a 9 % spread; the Rossby radius scales as 1/f, so a large domain feels it even though the range looks narrow.

Params(; coriolis = CoriolisParameter2D(-75.0))      # f-plane at 75°S
Params(; coriolis = CoriolisParameter2D(lat_matrix)) # varying with latitude

Fields

  • lat::Any: latitude in degrees north: a scalar (f-plane) or a full-domain matrix the size of mask
