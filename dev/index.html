Laddie.jl

Laddie.jl is a Julia implementation of LADDIE (Lambert et al. (2023); Lambert et al. (2026)), a model of the basal melt rate beneath an ice shelf. It treats the thin, buoyant meltwater layer in the cavity as a depth-averaged circulation, and runs on CPUs and GPUs through KernelAbstractions. Reactant.jl compiles the whole time loop with XLA to accelerate GPU runs, and the model is differentiable: a run can be differentiated with ForwardDiff.jl on the CPU and CUDA, and with Reactant and Enzyme for gradients at a cost that does not grow with the number of parameters.

The physics is that of LADDIE v2 on the grid of LADDIE v1; see LADDIE versions for how the two differ and which choice each option makes.

The model at a glance

Geometry and forcing go in, the one-layer plume model integrates them, and fields and restarts come out.

Inputs

Grid: domain mask, ice draft, bed and cell spacing.

CavityForcing: ambient ocean profiles and the ice temperature above the base.

Params: physics and numerical choices.

BoundaryConditions: wall, gap and open-ocean conditions.

Model

One layer under the ice. A single layer of thickness H carries depth-averaged velocities U, V and tracers T, S.

H U V T S

Melt, entrainment and density are set from the state at each step. The melt rate at the ice base is the main output.

Outputs

Basal melt rate, and the plume state, as time-averaged NetCDF.

Restarts as JLD2 files, continuing the same clock.

Provenance: run_metadata.toml with the parameters, forcing, grid and versions.

Each time step runs these stages in order. The later ones use the earlier ones' results.

Rotate the leapfrog levels and update the ambient fields.

Compute density and convection, then the basal melt and frazil ice.

Compute entrainment from the buoyancy flux and friction velocity.

Step the thickness, then the velocities, then limit the speed.

Step the temperature and salinity, then clamp them to their bounds.

Filter the leapfrog levels and advance the clock.

The physics and numerics overviews list each parameterisation and numerical choice, with its default. Time stepping has the leapfrog and filter details.

Examples

Each example is a page that runs a case end to end and compares it with a reference:

  • ISOMIP+: the idealised ISOMIP+ cavity, warm and cold, with a day-long comparison against the LADDIE v1 code.
  • Crosson–Dotson: reproduction of the realistic cavity run of Lambert et al. (2023).
  • Amundsen Sea: the Amundsen Sea Embayment, against LADDIE v2 output from Lambert et al. (2026).
  • Ice-shelf gaps: the two defensible treatments of an ice-free gap, on the geometries of Jesse et al. (2026).
  • Inverse problems: differentiating a run with respect to its parameters, with ForwardDiff.jl and Reactant.jl.
  • Reproducing published runs: every published LADDIE v1 and v2 setup that Laddie.jl has a preset for, compared with its published output.

Quick start

CPU example:

using Laddie

# Build and run the idealised ISOMIP+ warm cavity (CPU)
sim = build_isomip(; isomipcond = :warm)
run!(sim; days = 5.0)
mx, mn, sp = meltstats(sim)

GPU (CUDA example):

using CUDA, Laddie
sim = build_isomip(CUDABackend(); isomipcond = :warm)
run!(sim; days = 30.0)

Performance

Laddie.jl allocates its arrays on a chosen KernelAbstractions backend (CPU, CUDA, ROCm or Metal), so the entire time step executes on-device. Every term is a fused kernel, one pass per term with no intermediate arrays, so a time step allocates almost nothing. The same code runs multi-threaded on the CPU (julia -t N).
