Open-ocean boundary

At the ice front, and at the edges of gaps under SinkGapsBC, the layer meets the open ocean. Layer properties leave freely; what enters is set by BoundaryConditions(; open_ocean = ...):

  • ZeroGradientInflow, the default: all fields are extrapolated with zero gradient, so inflow from the ambient ocean carries the properties of the cell it enters.
  • NoInflow: where the flow enters through an ice-front face, the thickness and tracer fluxes carry the (zero) value stored in the open-ocean cell, so no volume, heat or salt is advected in. The velocities themselves are not clipped, and the momentum advection is unaffected.

The pressure gradient across the same faces is a separate choice; see Ice-front pressure gradient.

API

Laddie.AbstractOpenOceanBC — Type

Abstract supertype for the open-ocean boundary condition at the ice front. Pass a concrete instance as BoundaryConditions(; open_ocean = ...): ZeroGradientInflow (the default) or NoInflow.

source
Laddie.ZeroGradientInflow — Type
struct ZeroGradientInflow <: AbstractOpenOceanBC

Open-boundary condition at the ice front: zero-gradient extrapolation of all fields, with inflow from the ambient ocean permitted.

Select via BoundaryConditions(; open_ocean = ZeroGradientInflow()) (the default).

source
Laddie.NoInflow — Type
struct NoInflow <: AbstractOpenOceanBC

Open-boundary condition at the ice front: no inflow of layer properties. Where the flow enters the domain through an ice-front face, the thickness and tracer fluxes carry the (zero) value stored in the open-ocean cell instead of the zero-gradient extrapolation of ZeroGradientInflow, so no volume, heat or salt is advected in. The velocities themselves are not clipped, and momentum advection is unaffected.

Select via BoundaryConditions(; open_ocean = NoInflow()).
